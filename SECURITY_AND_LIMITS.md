# Security and limits

Guardian is a local single-user hackathon tool. Bind to loopback and run one application process. Existing GitHub URL validation, host/origin checks, clean subprocess environments, source size bounds, script-disabled metadata tools, and exact-version OSV matching remain in place.

## Implemented boundaries

- Intake accepts restricted public GitHub repository URLs. The HTTP API does not accept local filesystem paths or repository credentials.
- Discovery and detection run no repository build or installation scripts. Git, npm inspection, and Syft retain bounded execution and sanitized input/configuration.
- OSV supplies vulnerability matches. Heuristic change findings do not establish malware or runtime exploitability.
- Source evidence and pipeline checkpoints use SHA-256 hashes. Resume checks checkpoint content before reuse and reruns dependent modules after an upstream change.
- SQLite transactions protect job transitions and shared AI reservation counters. AI reservations are infrastructure only; there is no provider client in this milestone.
- Cancellation is cooperative. Running child process groups are terminated on the next polling check; network cancellation observes existing HTTP timeout boundaries.
- `.env` and `.env.*` are ignored except `.env.example`. Four empty key placeholders are provided. No key is needed for milestone 1.

## Current limitations

Verified native graph parsing supports npm package-lock v2/v3. Python `requirements.txt` and standard `pyproject.toml` dependencies are parsed as declarations. Exact pins use `declared_version`, not installed-version fields. Poetry, uv, Yarn, pnpm, and other unsupported lockfile formats remain detect-only. Python dependency groups, legacy tool metadata, includes, dynamic metadata, and installer options are not resolved.

Unlocked supported manifests can use deps.dev for bounded external graph inference. Only package names and selected versions are sent; source code, full manifests, credentials, and direct URL references are never transmitted. `inferred_version` and separate inferred edges describe possible generic-platform package graphs, not installed versions or joint repository resolution. Python requirements with markers or extras remain declarations without inference. A private index configuration is not reproduced; these are public-index observations only. No inference is an advisory source. Detection continues to query OSV only for verified exact npm lockfile versions; Python and inferred observations remain outside that verified vulnerability scope.

deps.dev failures preserve declarations and partial coverage. Bounds are forty requests and thirty seconds per scan, four MiB per response and sixteen MiB total bytes, twenty direct declarations, three thousand nodes and ten thousand edges per graph. HTTP requests do not follow redirects or use environment credentials. A 429/5xx or transport failure disables further inference calls for that scan, without automatic retries. Raw responses and hashes persist in separate discovery evidence, covered by checkpoints.

Milestone 3 adds bounded npm registry lifecycle-script retrieval, current-state script/name signals, and local policy enforcement. The default policy blocks Git-based references and unreviewed install scripts within supported metadata. Script review binds exact command bytes to a manifest/lifecycle or dependency name/version/lifecycle. The scanned repository cannot override Guardian's policy. Config errors, source tampering, unavailable script metadata, unsupported projects, and inspection limits prevent a clean policy pass. Policy failure means a review gate failed, not that the dependency is malware.

The detector reads at most 150 npm metadata files, inspects registry scripts for at most thirty flagged exact versions, checks up to 2,000 npm names against a pinned 1,000-name snapshot, and enriches at most ten name signals. Its shared metadata client permits sixty requests, forty-five seconds, two MiB per response, and ten MiB total response bytes. Only npm registry and deps.dev metadata endpoints are contacted. Redirects, environment credentials, tarball downloads, and automatic retries are disabled; 429/5xx or transport failure disables that host for the rest of the scan. Existing OSV bounds remain separate.

Missing `hasInstallScript` flags do not prove script absence. Registry metadata is a source statement, not verification of tarball content. Implicit native-build behavior may have no explicit command to review. Repository build/test scripts outside the supported lifecycle set, dependency tarball contents, unsupported managers, dynamic Python metadata, and arbitrary Python build backends are not inspected for execution behavior. No repository script runs.

Typosquat findings remain provisional review signals, even with several supporting heuristics. The pinned historical popularity list can be stale or manipulated and does not establish package trust. Names in different npm scopes are not compared. Indexed publication history is not known package creation age, and repository stars are only a popularity proxy. Missing enrichment is shown explicitly; heuristic confidence is not malware probability.

OSV `MAL-` advisory matches have a separate malicious-package label and count. Script/name/policy signals never manufacture CVEs or MAL matches. Withdrawn advisories remain excluded. Milestone 4 adds lexical JS/TS package reachability and deterministic priorities, with optional explanations. Milestones 5–6 add remediation, explicit approval, temporary rebuilds, validation, and the six-view UI.

The orchestrated pipeline stops at remediation with `blocked`. Discovery `completed` means discovery finished; it never means that all five modules or security verification passed. Partial detection and missing baseline evidence remain visible.

## Analysis and AI limits

Reachability is a lexical package-level model of the current workspace, not a full JavaScript parser, application entrypoint model, or function-level exploitability proof. Direct literal imports with verified graph bindings can be reachable; verified descendants inherit possible reachability. Test/type-only imports, dynamic loading, alias configuration, missing source, and unsupported ecosystems preserve uncertainty. `not_reachable` describes absence of an observed path in the supported static scope, never guaranteed runtime absence. Source inspection is capped at 2,000 files, ten MiB total, 512 KiB per file, 20,000 imports, and twenty witnesses per component.

Source severity is retained, including original advisory vectors and labels. CVSS parsing supplies a severity input to a separate deterministic priority formula. Priority and evidence confidence are review heuristics, not exploit probabilities or replacements for CVSS. Exploitation evidence is used only when explicitly present as an advisory-reported flag; no separate exploitation-intelligence service is configured.

AI receives validated IDs and deterministic fact categories, never source text, commands, titles, URLs, full repositories, or credentials in the prompt. Keys are sent only as authentication headers to the fixed Gemini host. HTTP clients reject redirects and environment credentials. Ollama is disabled until explicitly configured and is restricted to HTTP loopback endpoints. No local model is downloaded automatically.

The gateway validates output structure and references, permits one bounded repair within budgets, and falls back to labeled deterministic text. Schema validation cannot prove the truth of arbitrary generated prose. AI notes remain untrusted interpretations, cannot create findings or change scores, and never approve a patch. Compatible cached provider notes may be replayed when generation is disabled; their provider/model/cache provenance remains visible. Templates are not cached as AI results.

Default AI limits are three attempts per scan, thirty requests per UTC day shared across scans, and twelve seconds between requests. Failed generations, routing attempts, local attempts, and repairs count. Metadata checks share the daily counter and limiter, have a separate daily settings allowance, and never establish generation access or quota. Cooldowns and counters persist. A 429 cools the configured quota group; other keys in that group and model switching cannot bypass it. Project labels are operator declarations, not verified project identity. The default budget can end before all four keys or local fallback are tried. Each explanation task has a forty-five-second window, twenty-second maximum request duration, and 256 KiB response cap.

SQLite schema 2 adds AI state tables while retaining prior jobs and counters. Analysis checkpoints cover source evidence, outputs, and configuration/version hashes. Detection changes make exposed analysis stale. No Gemini key, key suffix, or per-key credential hash appears in API settings, reports, or sanitized usage events.

This is not an operating-system sandbox. Use a disposable isolated environment for hostile inputs. There is no authentication, multi-user isolation, distributed queue, automatic artifact retention, or aggregate disk quota. Checkpoint hashes detect accidental changes; a local attacker who controls the database and artifacts can rewrite both. Artifact stores are not signed or append-only.

Interrupted jobs require explicit resume. Usable partial checkpoints are reused rather than silently requerying changing advisory sources. Start a new scan or invalidate a checkpoint to refresh those results. An interrupted discovery without a usable checkpoint reclones the repository; it can resolve a newer commit. Previous workspaces are preserved under `workspaces-before-attempt-N` so detection selects only the current checkout. Completed discovery checkpoints retain the original pinned commit. Corrupt legacy status files and manually altered scan directories are not a supported recovery interface.

Milestone 2 verified live deps.dev access and real Syft against an explicitly labeled controlled npm/Python fixture. Milestone 3 additionally verified live OSV and npm metadata against a controlled locked fixture, with five vulnerability matches, three policy violations, seven review signals, and no scripts executed. MAL classification and withdrawal behavior were verified with synthetic advisory responses; the live fixture produced no verified MAL match. No live Gemini access, model availability, fresh GitHub intake, Docker isolation, or end-to-end remediation was verified. Existing opt-in GitHub/OSV integration tests remain separate from deterministic tests.

Milestone 4 verified source imports, deterministic priorities, separate import evidence, labeled templates, and safe settings through the API and browser. Its controlled fixture prioritized twelve findings, observed two directly imported packages, and used two template tasks with zero generation requests. No Gemini keys are configured here. Live Gemini/Ollama generation, project billing eligibility, and remaining quota remain unverified; routing, cooldown, repair, and cache behavior were tested with synthetic provider transports.

## Milestone 5 boundaries

Automatic remediation supports direct registry npm dependencies with package-lock v2/v3 in independent projects. Runtime dependency declarations must remain unchanged across candidate versions. Workspaces, Git/URL/local references, aliases, tags, overrides, resolutions, unsupported managers, transitive-only fixes and dependency-topology changes require manual resolution. Original constraints are checked; out-of-range upgrades require an explicit visible diff review. Exact candidate OSV no-match means only no matching advisory in that query, never proof a package is safe. Candidate checks have five attempts per package and plans have five proposals.

Lock regeneration runs offline with empty npm configs, clean environment, fixed registry and disabled scripts/audit/funding. Rebuilds require explicit registry URLs and integrity hashes for every package. Temporary validation copies exclude .npmrc, .env files and common credential paths. npm may download fixed-registry tarballs during approved ci; installation scripts never run. Host npm processing has application-level restrictions and process/file/time limits, not OS-level network isolation. No source checkout or Git history is changed.

Approvals bind source, original files, replacement files, exact diff and candidate evidence. Reviews persist and cannot be overwritten; a new plan needs new reviews. An API acknowledgement cannot establish human identity in this localhost single-user application. Local attackers controlling files and SQLite can rewrite both; hashes are not signatures. Plan and review mutation are serialized with existing worker ownership. Upstream changes make plans stale.

Optional Docker tests require explicit selection plus a preloaded digest-pinned image from operator configuration. No image is pulled. Network is disabled, root/source are read-only, privileges/capabilities are restricted, and CPU/memory/process/tmpfs limits apply. Build/test commands never run on the host. Docker is absent on this machine; the command boundary is tested synthetically, not verified against a live daemon. Missing tests, incomplete scans, missing validated SBOMs or baseline coverage prevent a full verification claim.

November 24, 2026 controlled verification used real OSV/npm/Syft and an automated fixture-only approval. lodash 4.17.20 upgraded to 4.18.1; four matched advisories were removed, no new advisory was found, and source script findings remained. Original files were unchanged; the installation sentinel never ran. Overall result was partial and build/tests not_run. No real user repository patch or human approval is claimed. Gemini generation remains unverified without credentials.

## Milestone 6 UI and demonstration

The six-view interface uses source-backed API data, textContent for untrusted content, self-only script/style CSP, bounded graph/finding displays, visible unknown/stale states, and distinct workflow/security outcomes. Route changes preserve scan identity; switching scans resets evidence and ignores obsolete asynchronous results. Original artifact downloads remain historical evidence, not a claim that a changed source is freshly validated.

The controlled-demo API accepts no repository path or URL. It creates only fixed intentionally vulnerable fixture bytes and uses live allowed-host intelligence. Every patch still requires an explicit immutable decision. Automated QA approvals are labeled fixture tests and never apply to user repositories. The regular GitHub pipeline API still rejects fixture URLs and local paths. The demo source contains an installation sentinel that must never execute; its absence and unchanged source digest were verified.

Cache warming uses the same real provider gateway and ordinary budgets. No synthetic model outputs or credentials are inserted into a live cache. Without real credentials, notes remain templates. Report replay is read-only. External intelligence requests and registry package downloads still occur during a new live demo; no offline-intelligence claim is made.

Live milestone 6 browser testing completed the full fixture flow with an automated test-only review, script-disabled temporary npm rebuild, real Syft and OSV/static rescan. Four advisory matches resolved and two source review signals remained. Build/tests stayed not_run because Docker is absent; overall verification stayed partial. A missing browser connector was handled with isolated headless Chromium, without using the user's browser profile. Desktop/mobile/landscape QA found no JavaScript errors or final page overflow. The optional browser harness installs no production frontend dependency.
